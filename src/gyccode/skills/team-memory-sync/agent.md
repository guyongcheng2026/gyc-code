# 团队内存同步 (team-memory-sync)

## 功能概述
这个技能展示了如何增强pi agent的协作能力，通过实现团队内存同步来提供：
1. 团队上下文共享机制
2. 经验和最佳实践的共享
3. 会话历史和学习的持久化
4. 多代理协作和知识传递
5. 与现有架构和工具的集成

## 当前限制
pi agent目前的协作能力有限：
- 每个会话都是孤立的，没有持久的团队记忆
- 没有机制在团队成员或会话之间共享上下文
- 经验教训和最佳实践无法在团队中传播
- 代理之间的知识传递受限
- 没有团队范围内的学习和改进机制

## 增强功能

### 1. 团队上下文共享
- 持久化的团队内存存储
- 会话上下文的自动保存和加载
- 项目特定的知识库（架构决策、编码标准、常见问题等）
- 角色和专长映射（谁在哪些方面有 expertise）
- 上下文感知的建议（基于团队的历史决策）

### 2. 经验和最佳实践共享
- 自动捕获成功的解决方案和模式
- 常见陷阱和错误的记录
- 最佳实践和编码标准的维护
- 经验教训的分类和标签系统
- 基于团队历史的智能建议

### 3. 会话历史和学习
- 会话的自动存档和索引
- 可搜索的会话历史（按主题、日期、参与者等）
- 学习曲线追踪和知识差距识别
- 重复问题的自动检测和预防
- 个人和团队的进步报告

### 4. 多代理协作
- 代理间的消息传递和知识共享
- 协作问题解决和头脑风暴
- 任务和结果的团队可见性
- 专长发现和代理推荐
- 一致的团队实践和标准

### 5. 与架构和工具的集成
- 与协调者-工作者模式集成：
  - 工作者可以将学习和发现贡献给团队内存
  - 协调者可以利用团队内存来做出更好的决策
  - 团队内存可以影响工作者的创建和分配
- 与技能系统集成：
  - 团队内存可以推荐相关的技能
  - 技能使用经验可以反馈到团队内存中
  - 最佳实践可以编码为可重用的技能
- 与现有工具集成：
  - 编辑工具可以基于团队内存提供建议
  - 搜索工具可以利用团队知识来改善结果
  - 验证代理可以从团队的过去经验中学习

## 实现方法

这个技能提供了一个如何实现这些增强功能的蓝图。实际的实现需要：
1. 创建团队内存管理器核心组件
2. 实施持久化存储机制（数据库、文件系统等）
3. 添加上下文捕获和共享功能
4. 实施经验和最佳实践的共享系统
5. 创建会话历史和学习机制
6. 实现多代理协作功能
7. 与现有架构（协调者-工作者模式）和工具集成
8. 提供用于配置团队内存行为和隐私的选项

然而，这个技能可以通过以下方式使用：
1. 作为参考文档，用于了解应该实现什么
2. 作为教学工具，帮助用户理解团队内存同步的好处
3. 作为原型，这些增强功能可以在此基础上进行构建

## 团队内存数据模型

团队内存可以包含以下类型的信息：

**上下文信息**：
- 项目架构决策和原因
- 编码标准和最佳实践
- 常见问题和解决方案
- API使用指南和示例
- 性能调优经验
- 安全考虑和修补

**会话历史**：
- 完整的对话记录（带时间戳）
- 采取的行动和做出的决定
- 使用的工具和执行的命令
- 生成的代码和修改的文件
- 遇到的问题和解决方案

**经验和最佳实践**：
- 成功的解决方案模式
- 常见错误和陷阱
- 性能优化技巧
- 安全最佳实践
- 代码审查发现和标准

**协作数据**：
- 代理专长和贡献
- 任务完成率和效率指标
- 知识共享和学习事件
- 最佳实践的采用和遵守情况

## 使用示例

### 示例1：项目上下文共享
新团队成员加入项目时：

团队内存响应：
```
欢迎加入项目！基于团队内存，这里有一些重要信息：

架构决策：
- 使用微服务架构，服务间通过REST API通信
- 选择PostgreSQL作为主数据库，因为需要复杂查询和事务
- 采用事件驱动设计处理高吞吐量操作
- 前端使用React + TypeScript，后端使用Node.js + Express

编码标准：
- 强制使用ESLint和Prettier
- TypeScript严格模式开启
- 函数最大长度：50行
- 所有公共API必须有JSDoc注释
- 数据库查询必须使用参数化以防止SQL注入

常见问题和解决方案：
- 问题：数据库连接池耗尽
  解决：增加最大连接数并实现连接泄漏检测
- 问题：前端性能卡顿
  解决：实现虚拟滚动列表和懒加载图片

团队经验：
- 上次性能优化使API响应时间降低40%
- 安全审计中发现并修复了3处潜在的XSS漏洞
- 新成员建议：首先阅读ARCHITECTURE.md和CODING_STANDARDS.md
```

### 示例2：经验共享和最佳实践
开发过程中遇到问题时：

团队内存响应：
```
基于团队经验，这里有一些针对您当前问题的建议：

相似过去经验：
- 您遇到的“间歇性超时错误”在上个月的认证服务中也出现过
  解决方案：增加了超时时间并添加了重试机制
  参考：提交abc123def和团队内存条目TM-2026-08-15-001

最佳实践提醒：
- 所有外部服务调用都应有超时和重试机制
- 数据库查询超过100ms应记录为慢查询
- 新功能发布必须包括监控和告警设置

建议行动：
1. 检查是否超时设置太低
2. 添加指数退避重试机制
3. 实现详细的日志记录以便调试
4. 添加监控以追踪成功和失败率
```

### 示例3：多代理协作
在协调者-工作者模式中：

团队内存响应：
```
协作洞察：
- 验证代理Alex在过去一周发现了5个安全问题
- 探索代理Sam擅长发现架构不一致之处
- 规划代理Taylor的设计文档得到团队一致好评

知识共享机会：
- 验证代理Alex可以分享安全测试技巧
- 探索代理Sam可以演示高效的代码搜索策略
- 规划代理Taylor可以主持架构设计工作坊

团队建议：
- 下次迭代中，让验证代理Alex审查所有新端点的安全性
- 探索代理Sam可以带领一次代码库搜索技巧的分享会
- 考虑创建一个“最佳实践”代理来维护团队标准
```
