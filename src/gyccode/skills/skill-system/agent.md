# 技能系统 (skill-system)

## 系统概述
这个技能展示了如何增强pi agent的功能，通过实现基本的技能系统来提供：
1. 技能发现和注册机制
2. 动态技能加载和生命周期管理
3. 技能市场集成用于社区贡献的功能
4. 技能依赖管理和版本控制
5. 技能沙盒和权限隔离
6. 与现有架构（协调者-工作者模式）的集成

## 当前限制
pi agent目前具有：
- 硬编码的功能通过内置工具
- 现有的技能市场用于特定领域的技能（Google Cloud/Agent Platform）
- 没有通用的技能系统用于发现和加载社区贡献的功能
- 没有动态技能加载机制
- 没有技能依赖管理
- 没有技能沙盒或权限隔离

## 增强功能

### 1. 技能发现和注册
- 自动发现本地和远程技能
- 技能元数据标准（名称、版本、描述、依赖等）
- 技能注册表用于跟踫可用技能
- 搜索和过滤功能，用于按类别、标签等查找技能
- 版本控制以支持多个技能版本

### 2. 动态技能加载和生命周期管理
- 运行时加载和卸载技能
- 技能初始化和清理钩子
- 状态管理对于有状态的技能
- 热重载用于开发过程
- 错误隔离以防止一个技能的故障影响其他技能

### 3. 技能市场集成
- 与现有的gyc-code技能市场集成
- 支持远程技能仓库（GitHub、GitLab等）
- 技能发布和更新机制
- 下载和安装自动化
- 更新通知和版本管理

### 4. 技能依赖管理
- 声明性技能依赖（其他技能、库、工具等）
- 依赖解析和安装
- 版本冲突检测和解决
- 可选依赖和特性标志
- 依赖图可视化

### 5. 技能沙盒和权限隔离
- 技能特定的权限声明
- 运行时权限检查和强制执行
- 文件系统访问限制（每个技能的沙盒）
- 工具访问控制（技能只能使用声明的工具）
- 网络访问控制（出站连接限制）
- 资源限制（CPU、内存、磁盘使用）

### 6. 与架构的集成
- 与协调者-工作者模式集成：
  - 技能可以声明它们是否可以作为工作者使用
  - 技能可以指定它们需要的工具集
  - 工作者可以从技能系统动态加载
- 与现有工具集成：
  - 技能可以扩展或修改现有工具行为
  - 技能可以注册新工具供系统使用
- 与用户界面集成：
  - 技能可以贡献命令、菜单项和快捷键
  - 技能可以提供自己的用户界面组件

## 实现方法

这个技能提供了一个如何实现这些增强功能的蓝图。实际的实现需要：
1. 创建技能管理器核心组件
2. 实现技能发现和注册机制
3. 添加动态技能加载和生命周期管理
4. 集成技能市场功能
5. 实施技能依赖管理系统
6. 添加技能沙盒和权限隔离
7. 与现有架构（协调者-工作者模式）和工具集成

然而，这个技能可以通过以下方式使用：
1. 作为参考文档，用于了解应该实现什么
2. 作为教学工具，帮助用户理解技能系统的好处
3. 作为原型，这些增强功能可以在此基础上进行构建

## 技能元数据标准

每个技能应该有一个`agent.json`文件，包含：

```json
{
  "id": "唯一技能标识符",
  "name": "人类可读的技能名称",
  "main": "主要内容文件（通常是agent.md）",
  "description": "技能功能的简短描述",
  "version": "语义版本号（MAJOR.MINOR.PATCH）",
  "author": "技能作者",
  "category": "技能类别（development、testing、documentation等）",
  "dependencies": ["其他技能ID的列表"],
  "mcp_servers": ["所需的MCP服务器列表"],
  "usage": ["使用说明字符串列表"],
  "status": "active/inactive/deprecated",
  "tags": ["用于搜索和过滤的标签列表"],
  "homepage": "技能主页的URL",
  "repository": "技能源码仓库的URL",
  "license": "许可证标识符（MIT、GPL等）",
  "localPath": "技能在本地文件系统中的路径",
  "publishedAt": "发布时间戳（ISO 8601格式）"
}
```

## 使用示例

### 示例1：发现和安装技能
用户输入：查找与测试相关的技能

技能系统响应：
```
找到的测试相关技能：
1. gyc-test-generation - 根据代码自动生成单元测试和集成测试
2. test-enhancement - 增强的测试工具和断言库
3. coverage-analysis - 代码覆盖率分析和报告工具

输入技能ID以查看详细信息或安装。
```

用户输入：安装 gyc-test-generation

技能系统响应：
```
正在安装 gyc-test-generation v1.0.0...
检查依赖：无依赖
从市场下载...
验证签名...
安装到本地技能目录...
注册技能...
 gyc-test-generation v1.0.0 安装成功！
```

### 示例2：使用技能
用户输入：/gyc-test-generation src/utils/helpers.ts

技能系统响应：
```
正在使用 gyc-test-generation v1.0.0 生成测试...
分析源码...
识别函数：helperFunction, processData, validateInput
生成测试文件：src/utils/__tests__/helpers.test.ts
测试覆盖率：函数覆盖率 90%，分支覆盖率 75%
测试已成功生成！
```

### 示例3：开发新技能
用户希望创建一个新的代码格式化技能

技能系统响应：
```
要创建一个新技能：
1. 在src/gyccode/skills/目录下创建一个新目录
2. 创建agent.json文件，包含技能元数据
3. 创建agent.md文件，包含技能功能和使用说明
4. 可选：创建KNOWLEDGE和RULE目录以存放额外资源
5. 使用 /skill-system register <技能路径> 注册技能
6. 技能将可用于发现和安装

例如：
mkdir -p src/gyccode/skills/code-formatter
创建agent.json和agent.md文件
/skill-system register src/gyccode/skills/code-formatter
```

## 与pi agent的集成

要将这些增强功能集成到pi agent中：
1. 创建技能管理器核心组件
2. 实现技能发现和注册机制
3. 添加动态技能加载和生命周期管理
4. 集成技能市场功能（基于现有的市场客户端）
5. 实施技能依赖管理系统
6. 添加技能沙盒和权限隔离
7. 与现有架构（协调者-工作者模式）和工具集成
8. 提供用于管理技能的命令行界面
9. 确保适当的错误处理和后备机制

此技能作为实施这些更改的规范和参考。
