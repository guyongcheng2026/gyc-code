# 协调者-工作者模式 (coordinator-worker)

## 架构概述
这个技能展示了如何增强pi agent的架构，通过实现协调者-工作者模式来提供：
1. 专门化的代理用于不同任务（规划者、验证者、探索者等）
2. 受限的工具访问以提高安全性和专注度
3. 会话状态管理和模式匹配
4. 工作流编排和任务委托
5. 与现有技能和工具的集成

## 当前限制
pi agent目前采用的是单一代理模式：
- 一个通用助手处理所有任务
- 对所有工具具有完全访问权限
- 没有专门化的代理用于不同的任务类型
- 没有受限的工具访问以提高安全性
- 没有复杂任务的工作流编排

## 增强功能

### 1. 协调者-工作者架构
实现一个协调者可以创建和管理专门工作者的系统：
- **协调者**：负责任务规划、工作者创建、监督和结果编译的中央代理
- **工作者**：具有特定工具集和职责的专门代理
- **任务委托**：协调者将复杂任务分解并分配给适当的工作者
- **结果编译**：协调者收集和综合工作者的结果

### 2. 专门代理类型
实施用于不同任务的专门工作者：
- **规划代理（Planning Agent）**：
  - 只读模式，禁止文件修改
  - 专注于探索代码库、理解架构和设计实现
  - 使用glob、grep、文件读取和只读bash命令
  - 提供结构化的规划输出
  
- **验证代理（Verification Agent）**：
  - 专注于寻找实现中的缺陷
  - 具有特定于更改类型的验证策略（前端、后端、CLI等）
  - 允许在临时目录中进行安全实验
  - 强调尝试破坏实现而不是仅仅确认其有效性
  
- **探索代理（Explore Agent）**：
  - 专门的文件搜索和分析专家
  - 只读模式
  - 在彻底程度和速度之间取得平衡
  
- **通用代理（General Agent）**：
  - 具有完整工具集的标准助手
  - 用于一般目的的编码任务
  
- **特定任务代理**：
  - 为特定任务（如测试生成、文档创建等）定制的工作者

### 3. 受限工具访问
为不同的工作者实施工具限制：
- **只读工具集**：用于规划/探索（文件读取、glob、grep、只读bash）
- **受限修改集**：用于特定任务（受限的文件编辑、特定的bash命令）
- **完整工具集**：用于通用代理（所有工具）
- **安全沙盒**：用于不受信任的操作（临时目录、受限的系统访问）

### 4. 会话和状态管理
- 会话模式匹配：在会话之间恢复协调者/工作者状态
- 工作者生命周期管理：创建、监督和终止工作者
- 任务队列和调度：管理工作者的任务分配
- 结果聚合：从多个工作者编译结果
- 通信机制：协调者和工作者之间的消息传递

### 5. 工作流编排
- 任务分解：将复杂任务分解为较小的、可管理的单元
- 依赖管理：处理任务之间的依赖关系
- 并行执行：在适用的情况下允许工作者并行工作
- 错误处理：管理工作者失败和重试
- 进度跟踪：监控任务完成情况和工作者状态

## 实现方法

这个技能提供了一个如何实现这些增强功能的蓝图。实际的实现需要：
1. 修改pi agent的核心架构以支持协调者-工作者模式
2. 实现工作者创建和管理系统
3. 定义专门的工作者类型及其工具集
4. 添加会话和状态管理功能
5. 实现任务委托和结果编译机制
6. 与现有技能和工具集成

然而，这个技能可以通过以下方式使用：
1. 作为参考文档，用于了解应该实现什么
2. 作为教学工具，帮助用户理解协调者-工作者模式的好处
3. 作为原型，这些增强功能可以在此基础上进行构建

## 使用示例

### 示例1：代码库探索任务
用户请求：“探索这个代码库以了解其架构并建议改进”

协调者-工作者工作流：
1. 协调者接收请求并将其分解为：
   - 代码库结构探索（分配给探索代理）
   - 架构分析（分配给规划代理）
   - 改进建议（分配给规划代理）
2. 探索代理：
   - 使用glob和grep查找关键文件
   - 读取架构文档和README
   - 报告代码库结构和组织
3. 规划代理：
   - 分析探索代理的发现
   - 识别架构模式和潜在改进点
   - 生成结构化的改进建议报告
4. 协调者：
   - 编译所有代理的结果
   - 提供一份全面的探索和建议报告

### 示例2：验证代码更改
用户请求：“验证这个拉取请求中所做的更改”

协调者-工作者工作流：
1. 协调者接收请求并将其分解为：
   - 构建验证（分配给验证代理）
   - 测试验证（分配给验证代理）
   - 安全检查（分配给验证代理）
   - 性能验证（分配给验证代理）
2. 验证代理：
   - 每个都在其特定领域进行深入检查
   - 使用适当的工具（构建系统、测试运行器、安全扫描器等）
   - 专注于寻找缺陷而非仅仅确认功能
   - 在临时目录中进行安全实验
3. 协调者：
   - 编译所有验证代理的结果
   - 提供一份详细的验证报告，列出任何发现的问题

### 示例3：通用编码任务
用户请求：“为这个API端点创建一个新功能”

协调者-工作者工作流：
1. 协调者确定这是一个通用任务
2. 分配给具有完整工具集的通用代理
3. 通用代理：
   - 使用所有可用工具完成任务
   - 根据需要访问专门代理以获取特定子任务
4. 协调者：
   - 接收并审查通用代理的结果
   - 提供最终输出

## 与pi agent的集成

要将这些增强功能集成到pi agent中：
1. 修改核心架构以支持协调者-工作者模式
2. 实现工作者创建和管理系统
3. 定义专门的工作者类型（规划者、验证者、探索者等）及其工具集
4. 添加会话和状态管理功能
5. 实现任务委托和结果编译机制
6. 与现有技能和工具集成
7. 提供用于配置工作者行为和限制的选项
8. 确保适当的错误处理和后备机制

此技能作为实施这些更改的规范和参考。
