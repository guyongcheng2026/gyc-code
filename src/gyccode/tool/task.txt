Launch a new agent to handle complex, multistep tasks autonomously. You must specify a subagent_type to select which agent type to use.

When NOT to use the Task tool:
- One specific file path → use Read or Glob; a class definition or a specific file set of 2-3 files → use Grep/Read directly.
- If no available agent is a good fit, use other tools directly.

Usage notes:
1. Launch multiple agents concurrently whenever possible (multiple tool uses in a single message).
2. Once you have delegated work to an agent, do not duplicate that work yourself. Continue with non-overlapping tasks, or wait for the result. Background tasks notify you automatically when done.
3. The agent's result is not visible to the user — relay a concise summary in your reply. Its final message includes a task_id you can reuse later to resume that subagent session.
4. Each invocation starts with a fresh context unless you provide task_id to resume it (continuing its prior messages and tool outputs). When starting fresh, give a highly detailed autonomous task description and specify exactly what information the agent should return in its final and only message.
5. The agent's outputs should generally be trusted.
6. Clearly tell the agent whether you expect it to write code or just research (search, file reads, web fetches) — it is not aware of the user's intent. Tell it how to verify its work if possible (e.g. test commands).
7. If the agent description says it should be used proactively, use it without waiting to be asked; use your judgement.
