## 1. agent-review-skill — 智能体合规审核

| 属性 | 内容 |
|------|------|
| 版本 | 2.0.1 |
| 开发者 | YG 内部 |
| 分类 | 开发 |

**作用**: 自动化审核智能体（Agent）的合规性，检查是否符合公司标准目录结构规范。涵盖 6 大检查维度：目录结构、agent.json 格式与字段、主文件完整性、逻辑功能合理性、安全合规性、文档可维护性。

**使用场景**:
- **开发自检**: 开发者在提交智能体前运行自检
- **审核流程**: 作为智能体审核流程的一环，由审核人执行

**输入**: 智能体目录路径 或 ZIP 压缩包
**输出**: Markdown 格式的审核报告，保存到 `ai.doc/agent-test/reports/`

## 2. api-metric — API 性能问题诊断与优化

| 属性 | 内容 |
|------|------|
| 版本 | 1.0.0 |
| 开发者 | 罗剑光 |
| 分类 | 优化 |

**作用**: 专门针对 Java8 + Spring Boot 2.3 技术栈的 RESTful API 进行性能问题定位与优化分析。根据 API 的异常指标（响应时间、数据大小、调用次数等），逐层分析关联代码，输出具体的优化点和代码级优化方案。

**使用场景**:
- **API 慢查询优化**: 用户反馈 API 响应慢时，定位数据库访问、远程调用、Redis 访问等瓶颈
- **代码审查优化**: 评审 API 实现代码中的性能隐患
- **SQL 优化**: 结合表索引和预计数据规模，优化 SQL 执行计划

**输入**: API 编号 / API 入口 Java 类 + 方法名
**输出**: 优化点清单 `{API编号}_0_优化点清单.md` + 按优化点分别输出 `{API编号}_{优化点名称}.md`

## 3. test-case — 测试用例编写

| 属性 | 内容 |
|------|------|
| 版本 | 1.0.3 |
| 开发者 | YG 内部 |
| 分类 | 测试 |

**作用**: 根据需求文档（MD/DOCX）和历史测试用例，按"九天测试用例模板"生成完整的测试用例。遵循增量变更原则，只修改受新需求影响的历史功能，并补充完整的新功能测试用例。

**使用场景**:
- **新功能测试**: 需求文档完成后，自动生成功能测试用例
- **需求变更测试**: 已有历史测试用例的项目发生需求变更时，增量更新测试用例
- **回归测试**: 补充回归测试所需的测试用例

**输入**: 需求文档（MD 或 DOCX）、历史测试用例（可选）
**输出**: `.tsv` 格式文件 — `{功能名称}_测试需求.tsv` + `{功能名称}_测试步骤.tsv`

**流程**: 准备 → 分析功能点 → 梳理业务场景 → 编写业务场景测试 → 设计测试 → 完善测试内容 → 整合 → 复核

## 9. yg-code-review — 代码审查

| 属性 | 内容 |
|------|------|
| 版本 | 1.0.0 |
| 开发者 | 罗剑光 |
| 分类 | 开发 |

**作用**: 对 Java、TypeScript、JavaScript、SQL、Python、YJPL、C# 等代码进行深度质量审查。按 1 级（逻辑缺陷/性能/安全）、2 级（安全性/可扩展性）、3 级（可维护性）分类输出问题报告。

**使用场景**:
- **代码审查**: Pull Request 或代码提交前进行全面审查
- **Java 审查**: 线程安全、内存泄漏、锁粒度、死锁
- **前端审查**: 内存泄漏、大型数据处理、异步处理、重渲染
- **SQL 审查**: 大数据量/高并发场景下的性能问题和死锁风险

**输入**: 待审查的源文件（支持多个，以空格分隔）或 `@git-changes`
**输出**: `审查报告/{1级问题数}_{2级问题数}_{3级问题数}_{文件名}.md`

**支持的文件类型**: .java / .ts / .js / .sql / .py / .yjpl / .cs

## 10. yg-dynamic-sql — 动态 SQL 改造

| 属性 | 内容 |
|------|------|
| 版本 | 1.0.0 |
| 开发者 | YG 内部 |
| 分类 | 开发 |

**作用**: 将 Java 代码中以字符串拼接方式编写的 SQL 语句，以及旧的动态 SQL 配置 XML 文件，改造为 MyBatis 原生 XML 配置格式。支持 Oracle 和 MySQL 双数据库兼容。

**输入**: 
- 旧的动态 SQL 配置 XML（可选）
- 含 SQL 字符串拼接的 Java 文件
- 分批次改造计划

**输出**: 
- `src/main/resources/META-INF/mapper/{类名}.xml`（MyBatis XML）
- Mapper 接口 `I{类名}Mapper.java`
- `动态sql改造计划/{java类名}.md`（批处理计划）
