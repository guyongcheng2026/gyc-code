# 第一章 项目概述

## 1.1 项目背景

### 1.1.1 政策驱动

近年来，国家层面围绕供应链管理体系的数字化、智能化、自主可控出台了一系列重大政策，为央企电子商城系统的重构升级提供了明确导向和刚性要求：

**（1）供应链管理政策要求**

国务院国资委《关于中央企业在建设世界一流企业中加强供应链管理的指导意见》（2023年），明确提出："通过标准引领、数据互联、生态构建等方式，打造一批整合力强、协同性高、辐射面广的供应链平台，推动上下游企业互联互通，提升产业链供应链韧性和安全水平。"

**（2）人工智能+战略部署**

国务院《关于深入实施"人工智能+"行动的意见》（2024年8月），提出"以科技、产业、消费、民生、治理、全球合作等领域为重点，深入实施'人工智能+'行动。加快人工智能在各类公共资源招标投标活动中的应用，提升智能交易服务和监管水平。"

**（3）数智供应链专项行动计划**

商务部等8部门《加快数智供应链发展专项行动计划》（2025年3月），提出："运用人工智能、物联网、区块链等新技术，'一链一策'推进供应链数字化、智能化、可视化改造，增强需求预测、智能决策、风险感知、自我修复等能力。到2028年，形成一批引领带动的数智供应链企业，实现供应链整体效率和服务质量显著提升。"

**（4）信创国产化刚性要求（核心紧迫性）**

国资委《关于在中央企业加快推进信息化系统信创国产化工作的通知》（79号文）明确要求：到2027年底前，中央企业必须实现信息化系统的信创国产化替代。SAP ECC系统已于2025年12月31日起陆续停止服务，涉及全国央企39套以上系统，2027年全面停止。

**（5）"十五五"规划与数字经济战略**

国家"十五五"规划明确提出推动数字经济与实体经济深度融合，央企数字化转型是其中的重点任务。国有资产监管要求央企在2028年前实现采购供应链管理的全面数字化和智能化。

**政策驱动因素总结：**

| 政策文件 | 核心要求 | 对本项目的影响 |
|----------|---------|--------------|
| 国资委供应链管理指导意见 | 打造整合力强、协同性高的供应链平台 | 产品定位为通用型央企电子商城平台 |
| "人工智能+"行动意见 | 公共资源招投标应用AI技术 | 智能寻源、智能评标等模块设计 |
| 数智供应链专项行动计划 | "一链一策"推进数智化改造 | 行业模板+配置化策略 |
| 国资委79号文（信创国产化） | 2027年底前完成国产化替代 | 信创技术底座，自主可控架构 |
| SAP ECC停服路线图 | 2027年全面停服 | ERP集成与替代需求 |
| "十五五"规划 | 数字经济与实体经济深度融合 | 多租户SaaS模式、数据要素流通 |

### 1.1.2 市场机遇

当前，除国家电网以外的央企和地方国企（简称"非国网央企+地方国企"）在电子商城系统方面面临以下共性挑战：

**（1）共性痛点**

- **系统碎片化**：约70%的非国网央企仍在使用分散的采购系统，缺乏统一的电子商城平台
- **数据孤岛严重**：采购数据、供应商数据、库存数据分布在不同系统中，无法贯通共享
- **智能化水平低**：仍以人工操作为主，缺少AI辅助的寻源、评标、采购预测等能力
- **信创压力**：2027年国产化替代deadline临近，大量SAP ERP系统面临迁移
- **规模效应不足**：单一央企的采购规模有限，无法形成有竞争力的供应商生态

**（2）市场规模估算**

根据公开数据：
- 中央企业98家（2025年国资委数据），除国家电网外约97家
- 重点地方国企约2000家（各省市国资系统）
- 年均采购金额合计约25万亿元（不含电力、电信等）
- 电子商城系统渗透率不足30%，市场空间巨大
- 产品升级换代需求：现有系统平均使用年限超过8年

**（3）市场空白点**

目前市场上尚缺少一个真正面向非国网央企和地方国企的、覆盖供应链全链路的通用型电子商城系统。现有方案多为：
- 定制化开发（成本高、周期长、不可复用）
- 单一功能产品（只覆盖寻源或商城某一环节）
- 国外平台（不满足信创要求，数据安全风险高）

### 1.1.3 产品定位

本系统定位为"**面向央国企的通用型电子商城系统**"，核心特征如下：

| 维度 | 定位描述 |
|------|---------|
| 目标客户 | 非国网中央企业（约90家）+ 重点地方国企（约2000家） |
| 产品形态 | SaaS平台（多租户）+ 私有化部署（信创适配）两大模式 |
| 功能范围 | 采购全生命周期7大环节全覆盖，AI+SaaS驱动 |
| 核心优势 | "国网商城能力底座 × 通用化配置 × AI融合 × 信创自主可控" |
| 差异化 | 平台80%通用 + 行业配置15% + 扩展定制5% |
| 竞争对手 | 无直接竞品（填补市场空白） |

**产品定位声明：**

> 本系统基于国家电网ECP2.0的成功实践经验，面向中央企业和地方国企供应链管理的通用需求，构建行业领先的电子商城产品。在业务上要覆盖国网商城的所有业务功能，并在通用化适配、AI融合、信创底座、多租户架构等方面实现超越。

## 1.2 项目目标

### 1.2.1 总体目标

**建成央企行业领先的供应链电子商城产品，实现"一套产品、多租户运营、全场景覆盖"。**

具体而言：
- 覆盖采购全生命周期7大核心业务环节（寻源、上架、下单、配送、支付、评价、供应商管理）
- 形成完整的数据闭环和管理闭环
- 建立可扩展的平台架构，支持行业模板快速适配
- 融入人工智能能力，实现智能寻源、智能推荐、智能预测等场景
- 完成信创国产化底座建设，100%自主可控

## 1.3 目标用户分析

### 1.3.1 终端用户分类

本系统涉及四类核心终端用户：

| 用户类型 | 角色描述 | 核心诉求 | 使用场景 |
|---------|---------|---------|---------|
| **采购方** | 央企/国企内部需求部门人员 | 便捷选品、快速下单、高效审批 | 商品搜索→购物车→请购审批→收货评价 |
| **供应商** | 入驻平台的供应商企业 | 入驻便捷、订单管理、对账结算 | 入驻申请→商品维护→发货→对账→结算 |
| **运营方** | 平台运营管理人员 | 规则配置、流程监控、数据统计 | 审批流配置→业务规则→数据分析→风险监控 |
| **监管方** | 企业内外部审计监察人员 | 合规审查、风险预警、全程追溯 | 合规审计→风险识别→问题追溯→报告生成 |

### 1.3.2 组织类型

| 组织类型 | 特征 | 典型用户 | 特殊需求 |
|---------|------|---------|---------|
| 央企集团（集团公司） | 多层级、多业态、跨区域 | 集团物资部、数字化部 | 集团统管、多业态适配、跨境支付 |
| 地方国企集团 | 中等规模、区域集中 | 市级/省级国资委管理单位 | 地方特色品类、区域物流适配 |
| 供应商企业 | 大中小微型均有 | 供应商运营人员 | 入驻便捷性、多平台管理 |

### 1.3.3 使用场景描述

**场景一：日常采购**
> 某央企二级单位物资专员张工，需要为下属三个部门采购办公设备和零星物资。登录系统后，通过智能搜索快速筛选符合预算的商品，加入购物车并提交请购单。系统自动根据品类金额触发不同级别的审批流，审批通过后订单自动生成并发送至供应商。供应商发货后，张工通过移动端扫码确认收货，系统自动完成对账结算流程。

**场景二：供应商入驻**
> 某制造企业"智造科技"希望在央企电子商城上架产品。注册账号后，填写企业信息、银行信息、上传资质文件，系统自动通过电眼查核验企业信息真实性。资质审核通过后，签署电子协议并完成电e宝签约，全程无纸化，3个工作日内完成入驻。

**场景三：运营监控**
> 平台运营管理员李经理登录管理后台，查看当日交易数据仪表盘。系统推送提示：某品类供应商集中度低于预警阈值，建议扩大寻源范围。李经理快速调整该品类的寻源规则，通过审批后立即生效。

**场景四：合规审计**
> 集团审计部通过系统导出本季度采购分析报告。系统自动标注异常指标：某类物资中标供应商集中度超80%，某审批节点耗时异常偏长。审计人员通过系统追溯功能，穿透查看原始订单、审批记录、供应商信息，形成完整的审计证据链。

| 独立数据库 | 每个租户独立数据库 | 大型租户、高安全要求 | 高 |

# 第四章 四大中心架构设计

## 4.1 中心化架构总览

电子商城系统采用"四大中心"业务架构，将通用业务能力沉淀为独立运行的微服务中心群，通过松耦合协同实现端到端采购供应链闭环。四大中心分别为：**用户与权限中心、业务规则中心、交易中心、流程中心**。

### 4.1.1 四大中心定位

| 中心 | 定位 | 核心职责 | 关键服务 |
|------|------|---------|---------|
| 用户与权限中心 | 身份基座 | 用户管理、组织映射、角色权限、统一认证 | user-service / org-service / auth-service / permission-service |
| 业务规则中心 | 决策大脑 | 规则配置、规则执行、预算管控、采购方式策略 | rule-service / budget-service / strategy-service |
| 交易中心 | 业务枢纽 | 购物车、报价、订单编排、支付结算 | cart-service / price-service / order-service / payment-service |
| 流程中心 | 协同引擎 | 工作流、状态机、事件驱动、任务调度 | workflow-service / state-machine-service / event-bus / task-service |

### 4.1.2 中心协同架构图

## 4.3 业务规则中心（BRC）

### 4.3.1 中心职责

### 5.4.2 评审打分模型

**商务评分（40%）**

| 评分项 | 权重 | 评分标准 |
|--------|------|---------|
| 报价 | 25% | 最低价为基准，按公式计算 |
| 资质 | 10% | 营业执照、行业资质、ISO认证 |
| 业绩 | 5% | 近3年同类项目业绩 |

**技术评分（50%）**

| 评分项 | 权重 | 评分标准 |
|--------|------|---------|
| 技术方案 | 25% | 方案合理性、完整性 |
| 产品性能 | 15% | 技术参数、质量指标 |
| 售后服务 | 10% | 服务响应、质保期 |

**价格评分（10%）**

按基准价公式计算：价格得分 = (基准价/报价) × 10 × 100

### 7.3.2 结算流程伪代码

```python
def checkout(user_id, cart_item_ids):
    """
    购物车结算：校验 → 拆单 → 创建订单 → 清空购物车
    """
    # 1. 获取选中的购物车商品
    cart_items = CartItem.query.filter(
        CartItem.user_id == user_id,
        CartItem.id.in_(cart_item_ids),
        CartItem.selected == 1
    ).all()

    if not cart_items:
        raise BusinessError('购物车为空')

    # 2. 库存校验（逐项）
    for item in cart_items:
        product = Product.get(item.product_id)
        if product.stock < item.quantity:
            raise BusinessError(f'商品 {item.product_name} 库存不足')
        if product.status != '在售':
            raise BusinessError(f'商品 {item.product_name} 已下架')

    # 3. 预算校验（调用业务规则中心）
    total_amount = sum(i.unit_price * i.quantity for i in cart_items)
    budget_check = call_brc_check_budget(user_id, total_amount)
    if not budget_check.passed:
        raise BusinessError(f'预算不足：{budget_check.message}')

    # 4. 按供应商拆分订单
    supplier_groups = group_by_supplier(cart_items)

    orders = []
    for supplier_id, items in supplier_groups.items():
        # 4.1 创建采购申请
        req = create_purchase_request(user_id, supplier_id, items)
        # 4.2 规则中心判定采购方式
        method = call_brc_determine_method(total_amount)
        # 4.3 流程中心发起审批流
        process = call_wfc_start_process('purchase_approval', req.id)
        # 4.4 创建订单（状态：待审批）
        order = create_order(req.id, user_id, supplier_id, items, method)
        # 4.5 预占库存
        for item in items:
            Product.reserve_stock(item.product_id, item.quantity)
        orders.append(order)

    # 5. 清空已结算的购物车项
    CartItem.query.filter(CartItem.id.in_(cart_item_ids)).delete()

    return orders
```

# 第十九章 资源投入评估

## 19.1 估算方法与基准

### 19.1.1 IFPUG CPM 4.3.1 标准功能点法

本项目采用IFPUG CPM 4.3.1（Counting Practices Manual）标准功能点法进行规模估算，该方法为ISO/IEC 14143国际标准，是目前软件行业最广泛使用的功能规模度量方法。

**功能点计数原理：**

IFPUG将软件功能需求划分为5种组件类型：

| 组件类型 | 缩写 | 定义 | 计数规则 |
|---------|------|------|---------|
| 内部逻辑文件 | ILF | 系统内部维护的逻辑数据组 | 数据功能（事务+数据） |
| 外部接口文件 | EIF | 系统引用但不在内部维护的数据 | 数据功能 |
| 外部输入 | EI | 从外部进入系统并更新ILF的处理 | 事务功能 |
| 外部输出 | EQ | 从系统向外部输出数据的处理 | 事务功能 |
| 外部查询 | EQ | 从系统中检索并输出数据的处理 | 事务功能 |

**加权计算公式：**
```
未调整功能点(UFP) = Σ(各类组件数 × 对应权重)
调整后功能点(AFP) = UFP × VAF
其中 VAF = (TDI × 0.01) + 0.65
```

### 19.1.2 CMMI 5级基准参数

本项目按CMMI 5级（优化级）组织进行估算，核心参数如下：

| 参数 | 符号 | 取值 | 来源 |
|------|------|------|------|
| 总影响度 | TDI | 40 | CMMI 5级标准值 |
| 价值调整因子 | VAF | 1.05 | VAF = (40×0.01)+0.65 = 1.05 |
| 开发生产率 | - | 10 FP/人月 | CMMI 5级行业基准 |
