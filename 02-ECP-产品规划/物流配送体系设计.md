# ECP物流配送体系设计

> 电子商城物流配送模块产品设计笔记
> 关联：前端原型 07-logistics

## 一、业务全景

ECP物流配送分为三大场景：

```
采购订单 → 供应商发货 → 物流追踪 → 到货验收 → 入库/退货
                                               ↓
                                         逆向物流（退货/换货）
```

### 1.1 配送模式

| 模式 | 说明 | 适用场景 | ECP支持度 |
|------|------|---------|----------|
| 供应商直发 | 供应商自行配送至指定地点 | 大宗设备/定制物资 | ✅ 当前主流 |
| 供应商物流 | 供应商委托第三方物流配送 | 通用MRO/办公用品 | ✅ 需物流信息回传 |
| 国网集配 | 国网统一仓储配送中心配送 | 通用备品备件 | ⏳ 规划中 |
| 自提 | 采购方到指定地点提货 | 紧急物资/就近提货 | ⚠️ 基础支持 |
| JIT配送 | 按生产计划定时送货 | 检修物资/生产物料 | ⏳ 高级场景 |

## 二、功能模块

### 2.1 物流追踪

核心需求：让采购方像查快递一样查订单物流状态。

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 物流轨迹信息回传 | 供应商应录入物流单号+承运商 | P0 |
| 物流状态可视化 | 类似快递100的进度跟踪页 | P0 |
| 多段运输追踪 | 干线+支线+最后一公里分段展示 | P1 |
| 预计到货时间 | 基于物流状态的ETA推算 | P1 |
| 物流异常预警 | 延迟/破损/签收异常自动告警 | P1 |

### 2.2 到货验收

| 环节 | 功能 | 说明 |
|------|------|------|
| 到货通知 | 自动通知采购方/仓库 | 物流签收后触发 |
| 收货确认 | 扫码/手动确认 | 关联采购订单行项 |
| 验收登记 | 数量/质量/文件验收 | 支持部分验收+差异记录 |
| 拒收处理 | 不合格品拒收流程 | 关联逆向物流 |
| EPR回写 | 验收结果同步至ERP | 触发库存增加/GI |

### 2.3 逆向物流（退货/换货）

```
退货申请 → 审核 → 退货通知 → 供应商回收 → 验收 → 退款/换货
```

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 退货申请 | 采购方发起，备注原因+附件 | P0 |
| 退货运单 | 系统生成退货物流单 | P1 |
| 质检退货 | 来料检验不合格→自动触发退货 | P1 |
| 换货流程 | 替换新订单+旧货回收 | P1 |
| 退款计算 | 按退货比例计算退款金额 | P1 |

## 三、数据模型（建议）

### 3.1 物流单（shipment）

```
shipment_id        PK
order_id           FK → 采购订单
shipment_type      enum: 直发/第三方/集配/自提
carrier            承运商名称
tracking_no        运单号
status             enum: 待发货/已发货/运输中/已签收/异常
estimated_arrival  预计到货日期
actual_arrival     实际签收时间
create_time
```

### 3.2 物流轨迹（tracking_event）

```
event_id           PK
shipment_id        FK
event_type         enum: 揽收/干线/中转/派送/签收/异常
location           经纬度/地点描述
operator           操作人
event_time         操作时间
remark             备注
```

### 3.3 验收记录（receiving_record）

```
receiving_id       PK
order_item_id      FK
received_qty       实收数量
defect_qty         不合格数量
receiving_status   enum: 全部通过/部分通过/全部拒收
inspector          验收人
inspection_time    验收时间
```

## 四、与供应商评分的关联

物流配送数据应作为**供应商绩效考核**的关键因子：

| 指标 | 权重建议 | 数据来源 |
|------|---------|---------|
| 准时到货率 | 20% | 物流追踪数据 |
| 配送完整性 | 10% | 验收差异记录 |
| 物流信息及时性 | 5% | 运单录入时效 |
| 逆向处理时效 | 5% | 退货处理周期 |

## 五、分阶段实施建议

| 阶段 | 功能 | 备注 |
|------|------|------|
| Phase 1（基础） | 物流单管理+运单回传+基础追踪 | 当前即可落地 |
| Phase 2（增强） | 物流轨迹可视化+异常预警+ETA | 需对接物流平台 |
| Phase 3（智能） | JIT配送+智能调度+物流数据分析 | 高级场景 |

**关键依赖**：物流轨迹对接需要选择物流平台集成方式（快递100 API、菜鸟物流云等），需评估数据安全合规。
