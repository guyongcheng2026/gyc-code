# 五E一中心对远光ECP产品规划启示录

> 本文基于六篇深度技术说明（ECP/EIP/ERP/ELP/e物资/ESC）的"对远光ECP的启示"部分进行整合提炼，形成可直接用于产品规划决策的综合建议文档。
> 元信息：创建时间2026-07-20

## 一、总体定位：远光ECP在五E一中心坐标系中的位置

```
国网五E一中心体系                    远光ECP对标定位
┌────────────────────┐             ┌──────────────────────┐
│  ECP（采购交易） ←──对标──→    │  核心能力（交易平台）  │
├────────────────────┤             ├──────────────────────┤
│  ERP（财务/库存） ←──接口──→    │  需对接（ERP适配层）  │
├────────────────────┤             ├──────────────────────┤
│  EIP（质量物联）  ←──延伸──→  │  差异化机会①（质量网关）│
├────────────────────┤             ├──────────────────────┤
│  ELP（电力物流）  ←──延伸──→  │  差异化机会②（物流跟踪）│
├────────────────────┤             ├──────────────────────┤
│  e物资（移动操作）←──覆盖──→  │  差异化机会③（移动端）  │
├────────────────────┤             ├──────────────────────┤
│  ESC（运营中心）  ←──借鉴──→  │  差异化机会④（AI运营）  │
└────────────────────┘             └──────────────────────┘
```

### 1.1 现状

远光ECP（国网商城B端）当前的核心能力集中在 **采购交易** 环节（ECP对标位），在质量数据对接、物流跟踪、移动操作、AI运营方面**尚属空白**。

### 1.2 战略建议

**三步走战略**：

| 阶段 | 定位 | 核心任务 | 对标L |
|------|------|---------|-------|
| **T1（0-6月）** | 交易平台优化 | 完善采购交易全流程，沉淀供应商/合同/订单核心数据 | 对标ECP基础能力 |
| **T2（6-18月）** | 供应链协同平台 | 打通质量数据（类EIP）+ 物流跟踪（类ELP）+ 移动端（类e物资） | 延伸至EIP/ELP/e物资 |
| **T3（18-36月）** | AI驱动的智慧供应链平台 | 数据中台+AI运营（类ESC）+ 财务一体化（类ERP） | 实现差异化竞争优势 |

## 二、各中心启示汇总

### 2.1 来自ECP的启示（对标核心能力）

**可直用**：

| 能力 | 远光ECP建议 | 优先级 |
|------|------------|--------|
| 投标工具U+模式 | 提供离线+在线混合的投标客户端，适应网络不稳定场景 | P1 |
| 框架协议采购 | 支持先签框架后下单模式，适用电力行业高频复购物资 | P0 |
| CA证书全链路 | 从注册到合同签署全程CA认证，确保法律效力 | P1 |
| 全流程监控 | 采购全过程可追溯、可审计，满足央企合规要求 | P0 |

**差异化优化方向**：

| 优化方向 | 说明 | P0/P1 |
|---------|------|-------|
| 轻量化Web投标 | 相比ECP的桌面客户端，远光ECP可提供Web版投标工具，降低部署门槛 | P0 |
| 移动端优先 | ECP的移动端较弱，远光ECP可强化移动审批、移动投标 | P1 |
| AI辅助评标 | 引入智能评标（资质自动对比、围串标识别） | P1 |
| 电商式采购体验 | MRO类物资提供类似京东的企业采购体验（搜索→加购→下单→审批→配送） | P0 |
| 供应商自服务门户 | 更好的供应商自助服务（一键资质维护、智能客服） | P1 |

### 2.2 来自EIP的启示（差异化①——质量数据网关）

**核心借鉴**：

| 建议 | 说明 | 优先级 |
|------|------|--------|
| 轻量化质量数据采集 | 对标EIP但做减法：提供Web填报+拍照上传+AI质检辅助，中小企业零门槛接入 | P1 |
| 与第三方检测机构对接 | 将检测报告、体系认证在线核验，替代人工接收 | P2 |
| 供应商质量画像 | 整合生产质量+到货验收+运行故障+售后数据，全生命周期供应商评价 | P1 |
| 质量闭环 | 验收结果与生产数据对照，发现差异自动触发处理流程 | P1 |

**集成架构建议**：

```
远光ECP（质量模块）
  ├─ 生产企业：Web填报 / 拍照上传 / API对接
  ├─ 第三方检测机构：报告在线核验
  ├─ 采购方：质量看板 + 异常预警 + 到货核验
  └─ 数据输出：供应商质量画像 + 行业质量趋势
```

### 2.3 来自ERP的启示（差异化②——采购到付款一体化）

**核心借鉴**：

| 建议 | 说明 | 优先级 |
|------|------|--------|
| 标准化ERP集成适配层 | 设计一个适配层，一套ECP对接SAP/用友/金蝶等多种ERP | P0 |
| 双向数据校验 | PO同步用"推送+确认"机制，防止数据不一致 | P1 |
| GR/IR闭环 | 收货与发票校验在ERP完成，ECP只获取结果状态，不处理财务细节 | P1 |
| P2P全链路可视化 | 从需求→招标→合同→订单→收货→发票→付款的全流程实时看板 | P0 |
| 物料主数据共享 | ECP与ERP共用物料编码体系，通过MDM实现一致 | P0 |

**适配层架构**：

```
远光ECP
  ↓
标准化集成适配器（Integration Adapter Layer）
  ├─ SAP接口适配器（RFC/IDoc/BAPI）
  ├─ 用友NC接口适配器（REST/SOAP）
  ├─ 金蝶云星空接口适配器（REST/WebService）
  └─ 自研ERP接口适配器（REST/JSON）
```

### 2.4 来自ELP的启示（差异化③——物流与仓储）

**三种接入方案**：

| 方案 | 实现方式 | 建议场景 | 优先级 |
|------|---------|---------|--------|
| **轻量级**（起步） | 对接快递100/菜鸟等物流API，供应商发货时填写物流单号自动跟踪 | MRO类物资、办公用品 | P0 |
| **标准级**（增强） | 对接国网ELP（如有权限），发货数据推ELP，物流状态回传ECP | 大型工程物资 | P2 |
| **完整级**（自建） | 自研WMS+TMS，支持第三方物流商对接，GPS+传感器实时跟踪 | 自营仓储业务 | P3 |

### 2.5 来自e物资的启示（差异化④——移动端）

**核心借鉴**：

| 建议 | 说明 | 优先级 |
|------|------|--------|
| 微信小程序接入 | 避免自研APP，基于微信/企业微信快速部署 | P0 |
| 离线优先设计 | 仓库/施工现场网络差，支持离线操作+在线同步 | P1 |
| 扫码驱动操作 | 条码/二维码一码到底，降低人工录入错误 | P0 |
| AI辅助识别 | 拍照识别物料铭牌（OCR），语音录入编码 | P2 |
| 移动审批 | 采购审批、合同审批、付款审批在移动端完成 | P0 |

**推荐技术选型**：

```
前端：微信小程序 + Vant UI
离线存储：小程序Storage + IndexedDB（上限50MB）
同步机制：任务队列 + 断点续传
扫码：微信原生扫码API
定位：微信JS-SDK GPS定位
拍照：微信原生拍照API
```

### 2.6 来自ESC的启示（差异化⑤——AI运营中心）

**三阶段建设路线**：

| 阶段 | 能力 | 技术实现 | 时间 |
|------|------|---------|------|
| **L1·看数据** | 采购驾驶舱（交易额/供应商/订单执行率） | 报表+ECharts大屏 | T1 |
| **L2·管风险** | 价格预警/供应商风险/履约监控 | 规则引擎+外部数据对接 | T2 |
| **L3·AI辅助决策** | 需求预测/智能评标/供应商画像 | 推荐算法+NLP+知识图谱 | T3 |

**AI场景优先级排序**：

| AI场景 | 价值 | 技术复杂度 | 优先级 |
|--------|------|-----------|--------|
| 采购数据驾驶舱 | 高 | 低 | P0 |
| 供应商风险预警（工商+司法） | 高 | 低 | P0 |
| 价格趋势分析 | 中 | 低 | P1 |
| 智能评标辅助（资质比对） | 高 | 中 | P1 |
| 需求预测 | 高 | 中 | P2 |
| 围标串标识别 | 中 | 高 | P2 |
| 供应商NLP画像 | 中 | 高 | P3 |
| 自动运营报告 | 低 | 中 | P3 |

## 五之一、数据架构落地支撑（基于ECP商城58表设计）

> 前述差异化机会（框架协议/电商体验/ERP集成/质量/物流/AI运营）若要真正落地，必须以可承载这些功能的**数据架构**为底座。已完成的《ECP与国网商城数据架构设计》（58张表）即为该底座，本节说明其与各差异化机会的映射关系。

### 5.1 差异化机会 → 数据表映射

| 差异化机会 | 核心数据表 | 关键字段/实体 | 设计文档 |
|-----------|-----------|--------------|---------|
| 电商式采购体验 | t_mall_product/SKU/cart/order/order_item/payment/review | SPU/SKU/购物车/订单/支付/评价全链路 | 国网商城电商域数据架构设计 |
| 框架协议采购 | t_ecp_contract(framework_flag) + t_ecp_framework_catalog + t_ecp_mall_order | 框架协议价格上限/起订量/执行订单 | ECP交易域数据架构设计 + 审查与细化(E6) |
| 全流程监控可审计 | t_ecp_audit_log + t_ecp_approval_log | 操作审计/审批流节点（等保2.0三级） | 审查与细化(E9/E10) |
| 标准化ERP集成 | t_mall_order.erp_po_no + t_mall_order_item.erp_po_item_id + t_ecp_contract.erp_po_no + t_mall_receipt.erp_gr_no + t_mall_invoice.erp_invoice_no | ERP采购订单号/收货凭证/发票号双向对照 | 审查与细化(字段ALTER) |
| 轻量化质量采集 | t_ecp_bid_qualification + t_mall_receipt(qc_result) | 投标资质/到货验收合格率 | 审查与细化(E2/M5) |
| 物流跟踪 | t_mall_shipment + t_mall_shipment_track | 物流单/轨迹(GPS/快递100) | 国网商城电商域数据架构设计 |
| 移动端 | t_mall_address + t_mall_message + t_mall_favorite | 地址簿/消息/收藏 | 审查与细化(M2/M10) |
| AI运营中心 | 跨域视图（供应商统一视图SQL已验证） | ECP合同+定标+商城店铺+订单聚合 | ECP商城业务流程SQL示例(Q7) |

### 5.2 已验证的跨域闭环（框架协议→商城下单）

数据架构已通过真实数据库验证，确认"框架协议采购→商城下单"业务闭环可落地：

```
t_ecp_contract(framework_flag=1)
   ↓ 合同ID
t_ecp_framework_catalog（价格上限/起订量/货期）
   ↓ 合同ID
t_ecp_mall_order（框架执行单）
   ↓ 订单号
t_mall_order（商城实际订单，含erp_po_no/budget_code/approval_flow_id）
```

验证报告见《ECP商城数据架构验证报告》（SQLite实测58表建库+8条关键SQL跑通，含上述闭环Q4）。

### 5.3 给产品规划的数据底座建议

1. **先建主数据层**：supplier/material/org/person/project 五张MDM表是所有业务的前提，应在T1阶段优先落地
2. **交易域与电商域共享主数据**：供应商/物料主数据被两个域复用，避免数据孤岛
3. **等保合规前置**：audit_log/approval_log 在T1即应纳入，而非事后补
4. **ERP集成字段预留**：即便暂不对接ERP，erp_po_no等字段应在建表时预留，避免后期大改表结构
5. **物理模型可直接导入**：已生成 PowerDesigner 物理模型 `ECP商城数据模型.pdm`（58表/750字段/109外键），供DBA直接评审

## 六、行动计划建议

### 5.1 立即启动（P0，0-3个月）

1. **电商式采购体验**：参照京东企业购模式，优化搜索/筛选/推荐/购物车/审批流
2. **框架协议采购**：支持协议供应商池管理+分批下单+竞价供货
3. **采购驾驶舱**：核心KPI看板（交易额、供应商数、订单执行率、节约率）
4. **微信小程序**：移动审批+订单查询+供应商门户
5. **快递物流API对接**：集成快递100，自动跟踪物流状态

### 5.2 中期建设（P1，3-9个月）
