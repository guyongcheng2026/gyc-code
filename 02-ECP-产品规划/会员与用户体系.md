# ECP会员与用户体系

> 电子商城采购方用户与会员体系设计笔记

## 一、用户模型

ECP的用户体系分三层：

```
采购方组织（国网省公司/地市公司）
    ↓
  采购部门/角色
    ↓
  采购员/审批人/财务/管理员
```

### 1.1 组织类型

| 类型 | 说明 | 权限范围 |
|------|------|---------|
| 采购方（国网体系） | 省公司/地市公司/直属单位 | 本组织采购+授权采购 |
| 供应商 | 注册供应商 | 报价/投标/接单/对账 |
| 平台运营方（远光） | 系统管理 | 全平台管理 |
| 监管方（国网物资部） | 监管审计 | 数据查看+报表 |

### 1.2 角色权限

| 角色 | 模块权限 | 说明 |
|------|---------|------|
| 采购员 | 采购寻源、下单、验收 | 日常操作 |
| 审批人 | 采购审批、合同审核 | 审批流程节点 |
| 财务人员 | 结算、发票、对账 | 财务操作 |
| 供应商管理员 | 供应商管理、绩效评价 | 管理供应商 |
| 系统管理员 | 组织配置、角色管理 | 运维管理 |
| 审计员 | 日志查看、报表导出 | 只读审计 |

## 二、会员体系

ECP不面向C端消费者，所以不做通用会员体系。但在B2B场景下可以有：

| 会员等级 | 条件 | 特权 |
|---------|------|------|
| 普通采购方 | 注册即得 | 基础采购功能 |
| 协议采购方 | 签订框架协议 | 协议价+账期 |
| VIB采购方 | 大额采购/长期合作 | 专属客服+优先履约 |

**注意**：B2B会员≠C端积分体系，特权应该围绕采购效率提升（价格、账期、服务），而非消费激励。
