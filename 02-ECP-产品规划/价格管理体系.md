# ECP价格管理体系

> 电子商城定价、调价、价格指数与监控体系设计笔记
> 关联：营销与促销体系、招投标评分模型

## 一、价格模型全景

ECP的价格体系是B2B多维度叠加结构：

```
       基准价（供应商挂牌价/目录价）
              ↓
        协议价（框架协议谈判折扣）
              ↓
        阶梯价（采购量×折扣率）
              ↓
        促销价（供应商临时折扣）
              ↓
       ┌────结算价（各类叠加后最终价）────┐
       │                                  │
   采购方可见价                     供应商结算价
```

### 1.1 价格类型

| 类型 | 定义 | 适用范围 |
|------|------|---------|
| 基准价 | 供应商挂牌/目录价格 | 全平台可见（参考价） |
| 协议价 | 框架协议约定的专属价格 | 特定采购方可见，优于基准价 |
| 阶梯价 | 按采购量分档折扣 | 批量采购场景 |
| 竞价结果价 | 招投标确定的成交价格 | 中标供应商锁定 |
| 促销价 | 供应商限时折扣价 | 限时有效 |
| 市场参考价 | ECP平台基于历史交易生成的价格参考 | 采购决策参考 |

## 二、价格管理流程

### 2.1 价格设置

```
供应商提交价格申请
    ↓
系统校验（是否在合理区间）
    ↓
采购方审核（协议价需确认）
    ↓
价格生效 → 商品详情页更新
```

### 2.2 调价流程

| 场景 | 流程 | 控制规则 |
|------|------|---------|
| 协议价调整 | 供应商发起→采购方审核→生效 | 频率限制（季度最多1次） |
| 基准价调整 | 供应商自行调整 | 涨价需提前15天通知 |
| 阶梯价调整 | 供应商后台设置 | 各阶梯折扣不可冲突 |
| 促销价 | 供应商发起→自动审批（/需人工） | 促销周期+限时锁定 |

### 2.3 价格风控

| 规则 | 说明 |
|------|------|
| 价格上限 | 不得高于基准价的200%（防止虚标） |
| 价格下限 | 不得低于成本的80%（防止恶性竞争） |
| 价格平稳 | 单次调价幅度≤30%（防止价格操纵） |
| 协议价锁定 | 合同期内协议价不可变更 |

## 三、价格指数

### 3.1 价格指数体系

| 指数 | 算法 | 用途 |
|------|------|------|
| 采购价格指数（PPI） | 指定品类加权平均采购价 vs 基准期 | 采购成本趋势监控 |
| 品类价格波动率 | (最高价-最低价)/均价 | 供应商报价离散度 |
| 协议价优惠率 | (基准价-协议价)/基准价 | 协议谈判效果评估 |
| 综合采购成本指数 | ∑(品类采购价×采购占比) | 整体采购成本变化 |

### 3.2 价格分析看板

```
品类价格趋势图
  选定品类 → 展示近12个月价格波动曲线
  叠加：基准价曲线、ECP采购价曲线、市场参考价

价格排名
  同类商品不同供应商报价对比
  支持按价格/销量/评分排序

价格预警
  某品类均价上涨超过10% → 触发预警
  某供应商报价异常低于同行 → 触发调查
```

## 四、竞价与价格发现

ECP的招投标模块天生具备强大的价格发现功能：

| 竞价方式 | 适用场景 | 价格发现能力 |
|---------|---------|------------|
| 公开招标 | 大额采购/工程 | ⭐⭐⭐ 充分竞争 |
| 邀请招标 | 有限供应商竞争 | ⭐⭐⭐ 一定竞争 |
| 询比价 | 通用物资 | ⭐⭐ 多方报价对比 |
| 竞争性谈判 | 复杂需求 | ⭐⭐ 谈判后的最优价 |
| 单一来源 | 独家供应 | ⭐ 价格谈判为主 |

## 五、价格数据模型

```sql
-- 价格表
CREATE TABLE price (
    price_id         VARCHAR(32) PK,
    sku_id           VARCHAR(32) FK → 商品,
    price_type       ENUM('基准价','协议价','阶梯价','促销价'),
    unit_price       DECIMAL(18,2),
    currency         CHAR(3) DEFAULT 'CNY',
    min_quantity     INT,           -- 阶梯价最低采购量
    max_quantity     INT,           -- 阶梯价最高采购量
    buyer_org_id     VARCHAR(32),   -- 协议价指定采购方（可选）
    effective_date   DATE,
    expiry_date      DATE,
    status           ENUM('待审核','已生效','已过期','已失效'),
    created_by       VARCHAR(32),
    created_at       TIMESTAMP
);

-- 价格变更日志（审计追溯）
CREATE TABLE price_change_log (
    log_id           VARCHAR(32) PK,
    price_id         VARCHAR(32) FK,
    old_price        DECIMAL(18,2),
    new_price        DECIMAL(18,2),
    change_reason    TEXT,
    operator_id      VARCHAR(32),
    approved_by      VARCHAR(32),
    change_time      TIMESTAMP
);
```

## 六、与其他模块的关系

| 模块 | 价格关联 |
|------|---------|
| 订单 | 订单金额 = ∑(结算价 × 数量) |
| 结算 | 结算单金额 = 已确认收货 × 结算价 |
| 招投标 | 评标中的价格分 = f(报价vs基准价) |
| 供应商绩效 | 价格得分 = f(供应商报价vs同类均价) |
| 预算控制 | 采购金额 ≤ 预算额度 × 调价系数 |

## 七、分阶段建设

| 阶段 | 能力 | 说明 |
|------|------|------|
| Phase 1 | 基准价+协议价管理 | 基本价格管理能力 |
| Phase 2 | 阶梯价+促销价+调价审批 | 价格灵活性提升 |
| Phase 3 | 价格指数+趋势分析 | 采购决策支持 |
| Phase 4 | 智能定价+自动调价建议 | AI辅助定价 |
