# ECP风控与交易安全

> 电子商城业务风控与交易安全保障体系设计笔记
> 关联：实施保障与风险控制（项目风险）、供应商绩效考核

## 一、风控全景

ECP业务风控覆盖三大领域：

```
供应商风险                交易风险                 采购方风险
  ┌─────────┐           ┌─────────┐            ┌─────────┐
  │资质造假  │           │围标串标  │            │预算超支  │
  │经营异常  │           │虚假交易  │            │审批违规  │
  │失信记录  │           │价格操纵  │            │利益输送  │
  │交付风险  │           │欺诈订单  │            │越权采购  │
  │关联关系  │           │重复结算  │            │数据泄露  │
  └─────────┘           └─────────┘            └─────────┘
```

## 二、围标串标检测（P0）

### 2.1 检测维度

| 检测项 | 算法/规则 | 阈值 |
|--------|----------|------|
| 投标IP相同 | 多个投标人使用同一IP提交 | 同一标段≥2家 |
| 投标MAC相同 | 设备物理地址相同 | ≥2家 |
| 文档属性雷同 | 投标文件作者、创建时间一致 | 高度怀疑 |
| 报价规律异常 | 报价存在固定比例关系（如A报价始终是B的95%） | 统计异常 |
| 投标保证金来源 | 多家投标保证金来自同一账户 | 一票否决 |
| 关联关系 | 投标人之间存在股权/人员关联 | 超过阈值标记 |

### 2.2 风控规则引擎

```
投标数据流入
    ↓
规则匹配（规则库可配置）
    ├── 命中高危规则 → 自动拦截 → 人工复核
    ├── 命中中危规则 → 标记预警 → 评标专家关注
    └── 命中低危规则 → 记录日志 → 事后审计
```

### 2.3 规则示例

```python
# 围标检测规则示例（伪代码）
def detect_collusion(bids):
    # 规则1：IP/MAC聚集
    clusters = bids.group_by(['ip_address', 'mac_address'])
    for cluster in clusters:
        if len(cluster.bidders) >= 2 and cluster.same_bid_section:
            return RISK_HIGH, f"多家投标人使用同一设备: {cluster.bidders}"
    
    # 规则2：报价规律异常
    price_pairs = analyze_price_ratios(bids)
    for pair in price_pairs:
        if pair.ratio_stable and pair.ratio != 1.0:
            return RISK_MEDIUM, f"报价存在固定比例: {pair.bidders}"
    
    # 规则3：投标保证金检查
    deposit_accounts = bids.get_deposit_accounts()
    for account, bidders in deposit_accounts.items():
        if len(bidders) >= 2:
            return RISK_HIGH, f"保证金来源相同: {bidders}"
```

## 三、供应商风险预警

### 3.1 风险监控

| 风险类型 | 数据来源 | 预警机制 |
|---------|---------|---------|
| 经营异常 | 企查查/天眼查API | 新增异常当日告警 |
| 涉诉信息 | 中国裁判文书网 | 涉采购类诉讼即时预警 |
| 失信被执行 | 最高法院失信名单 | 一键入库+冻结供应商 |
| 资质到期 | ECP平台登记数据 | 到期前30天/7天提醒 |
| 交付异常 | ECP订单数据 | 连续3次交付延迟→降级 |
| 财务风险 | 结算数据 | 对账差异率异常升高 |

### 3.2 供应商画像风险分

综合评分模型（可纳入供应商绩效体系）：

```
供应商风险分 = 30% × 信用风险 + 25% × 经营风险 + 25% × 履约风险 + 20% × 司法风险

风险等级：
  A（低风险）  ：0-20分，正常合作
  B（中等风险）：21-40分，加强监控
  C（高风险）  ：41-60分，限制新业务
  D（禁入）    ：60分+，冻结供应商
```

## 四、交易反欺诈

### 4.1 异常交易检测

| 场景 | 检测规则 |
|------|---------|
| 虚假订单 | 同一采购方短时间内大量下单后全部取消 |
| 刷单行为 | 供应商关联账号自买自卖 |
| 价格操纵 | 供应商联合抬高报价后再"优惠" |
| 退货异常 | 退货率异常升高（可能假货调包） |

### 4.2 实时风控

```
下单请求 → 实时风控检查（毫秒级）
    ├── 通过 → 继续订单流程
    ├── 可疑 → 进入人工审核队列
    └── 拦截 → 返回错误提示
```

## 五、采购方风险控制

| 风险 | 控制手段 |
|------|---------|
| 预算超支 | 订单金额 ≥ 预算可用额度 → 拦截 |
| 越权采购 | 采购品类超出采购员授权范围 → 审批升级 |
| 拆分采购规避招标 | 同一物资短期内多次采购累计金额超招标门槛 → 强制招标 |
| 利益输送 | 高频向特定供应商采购 → 系统预警 |
| 违规审批 | 审批人与采购人为同一人 → 强制交叉审批 |

## 六、数据风控与审计

| 能力 | 说明 |
|------|------|
| 全量审计日志 | 所有关键操作（增/删/改/查敏感数据）记录 |
| 数据脱敏 | 供应商银行账号、身份证等敏感字段自动脱敏 |
| 权限审计 | 定期检查权限分配合理性（最小权限原则） |
| 异常登录检测 | 异地登录、非工作时间高频率操作告警 |
| 操作追溯 | 任何业务操作均可追溯到操作人+时间+IP |

## 七、分阶段建设

| 阶段 | 能力 | 说明 |
|------|------|------|
| Phase 1 | 围标检测（基础规则）+供应商资质验真 | 规则引擎+企查查对接 |
| Phase 2 | 供应商风险预警+交易反欺诈 | 风险评分模型上线 |
| Phase 3 | 实时风控+采购方风险控制 | 在线风控决策引擎 |
| Phase 4 | AI风控（异常行为模式识别） | 机器学习模型+持续优化 |
