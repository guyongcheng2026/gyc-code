## 三、关键事实（避免重复劳动）

- **`cost_ledger` 插入失败**：投影表里的 JSON 列用 drizzle 查 `json_extract` + 分组会**静默返回空**，必须用裸 SQL。这是排查 `session.cost` 偏差时踩过的坑。
- **Windows 下 PowerShell 遇 `detached: true` 会「退出码 0 但输出全空」**（fd 与 pipe 两种形式均实测复现）。P0-4 因此在 win32 **不设 detached**，与前台路径 `shell.ts:499` 一致。教训：跨进程诡异行为先写最小复现脚本，别在业务代码里猜。
- **`session.cost` 历史偏差根因已查明**：运行计数器把已删除 part 的成本也累加，`sign=-1` 未完全抵消。实测某会话 `session.cost=7.6415` 而 part 合计 = message 合计 = `6.9049`（两条逐轮路径一致，偏离的是计数器本身）。append-only 已阻断新数据产生，历史需回填迁移（未做）。
- **被证伪的两个假设**（勿再尝试）：① `rollupUsage` 从未执行/step-finish 为 0 条 —— 错，实际 1340 条；② 差额来自子代理上卷 —— 错，数值接近属巧合。
- **shell 是 PowerShell**：命令用 `;` 分隔，`&&` 会报语法错。
- **node -e 内联脚本易被 PowerShell 转义破坏**：写脚本文件再执行。
