# 1.5x 超长会话压测报告（2026-10-18 实测）

**目标：** 验证 1.5 倍于历史最长会话（4000 message / 11600 part / 19.5MB part data，对比 2685/7739/12.4MB）下，会话加载路径的稳定性、内存与 U-3 对账正确性。

## 方法

- 生成器：`scripts/gen-synthetic-session.mjs`（bun:sqlite 写临时库，`--db` 指定，绝不触生产库）。行结构对齐 `SessionMessageTable`（data 列不含 id/type，decode 时由列注入，`src/core/session/history.ts:48-53`）；tool part 三态混入（completed/error/running 残留约 0.3%），输出体积参数化。
- 计时：`scripts/bench-long-session.mjs`。装配与生产一致：`@effect/sql-sqlite-bun` 的 `SqliteClient.layer` + `EffectDrizzleSqlite.makeWithDefaults()`，对 `SessionHistory.load`（含 U-3 对账）预热 1 次 + 计时 5 次取中位/P95。
- **踩坑记录：** drizzle 1.0.0-rc.2 必须用选项对象签名 `drizzle({ client })`（`src/core/database/sqlite.bun.ts:220` 同款）；位置参数 `drizzle(sqlite)` 会静默自开空连接，报「no such table」且与直查 sqlite_master 的结果自相矛盾，排查耗时较长，已写进 bench 注释。

## 数据（Bun 1.4.2 / Windows x64，本机实测）

| 库 | 行数 | tool part | part 字符量 | 库文件 | load p50 | p95 | RSS |
|---|---|---|---|---|---|---|---|
| 基线（≈1x） | 2580 | 7739 | 13.0MB | 15.8MB | **107ms** | 116ms | 222MB |
| 1.5x | 3868 | 11600 | 20.4MB | 23.7MB | **151ms** | 161ms | 380MB |

## 验收结论（全过）

1. **耗时**：1.5x p50=151ms ≤ max(基线×1.8, 2000ms)=192.6ms，实际放大比 1.41×（近线性）。
2. **内存**：RSS 380MB < 2GB 红线。
3. **解码**：0 解码错误（decode 失败会使 Effect 直接失败，未被触发）。
4. **U-3 对账规模化验证**：1.5x 库注入 12 条 running 残留，`SessionHistory.load` 后 `runningAfterLoad=0`（93e7717 的对账逻辑在真实加载路径生效且随规模稳定）。

## 已知限制

- 合成数据的 message 形态多样性低于真实会话（无 reasoning 密集、无超大单条 tool 输出、无附件路径），加载耗时结论可外推，压缩/截断行为需真实长会话补充观察。
- TUI 侧（OpenTUI 渲染、句柄预算、LRU 淘汰）未在无头环境覆盖；需原生终端用 `scripts/verify-tui.mjs --load-seconds` 目视验证，本轮未做。
- compaction 溢出判定（`src/gyccode/session/overflow.ts:73-95`）为纯函数且已有单测覆盖，本压测未重复覆盖其与 LLM 的集成路径。
