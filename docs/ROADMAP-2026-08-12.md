# gyc-code 去 opencode 化 Roadmap：自建后端三项（P1 剩余）

> 日期：2026-08-12
> 背景：`a86802e` 已完成 P1 低成本三项（Web UI 可配置 / 安装链路自持 / GitHub App 检测本地化）。
> 本文件规划剩余三项——它们依赖 opencode SaaS 后端，必须自建服务才能彻底移除
> `console.opencode.ai`、`dev.opencode.ai`、`opencode.ai/go` 三处引用。

---

## 总览

| # | 服务 | 现状依赖 | 替代方案 | 工作量 | 优先级 |
|---|------|---------|---------|--------|--------|
| 1 | 账号体系 | `console.opencode.ai`（OAuth 设备码 + 账号/Token 登录） | 自建 OAuth 服务 + 设备码流程 | 大（含 Web 控制台） | P1 |
| 2 | 会话分享 | `dev.opencode.ai` / `opencode.ai`（share 服务） | 自建分享 API + 渲染页 | 中 | P2 |
| 3 | 额度体系 | `opencode.ai/go` + `workspace/{id}/go`（免费额度升级页） | 自建配额/限流/升级入口 | 中 | P2 |

**统一原则**：新服务一律自研、MIT 双许可结构不变、TLS 加密、鉴权最小化、审计留痕（等保三级基线）。

## 一、账号体系（替代 console.opencode.ai）

### 现状依赖点
- `src/core/plugin/provider/gyccode.ts`：`defaultServer = "https://console.opencode.ai"`，设备码 OAuth（`Integration.MethodID.make("device")`），clientID `gyccode-cli`
- `src/gyccode/account/account.ts`：`defaultConsoleUrl = "https://console.opencode.ai"`，账号登录/Token 登录
- 作用：`gyc account login`、provider `gyccode`（免费模型网关认证）

### 自建方案
1. **服务端**（Bun + Effect + SQLite，与客户端同栈，复用 `@gyccode/protocol/v2` schema）：
   - OAuth 2.0 设备码授权（RFC 8628）：`POST /device/code`、`POST /device/token`
   - 账号体系：注册/登录（bcrypt）、JWT 会话、Token 管理、审计日志
2. **Web 控制台**（Vue3 + Element Plus，可复用 Geeker-Admin 风格）：设备码确认页、账号管理页
3. **客户端改造**：
   - `gyccode.ts` / `account.ts` 的默认端点改为环境变量 `GYCCODE_ACCOUNT_URL`，默认指向自建服务
   - 保留 opencode 端点作为**可配置的第三方兼容通道**（`GYCCODE_ACCOUNT_URL` 显式设置时启用，默认关闭）

### 验收标准
- `gyc account login` 全流程走自建服务，无 opencode 网络请求
- 默认关闭第三方通道；开启需显式配置
- 设备码、Token 刷新、登出、审计日志全部可用

## 二、会话分享（替代 dev.opencode.ai）

### 现状依赖点
- `src/gyccode/cli/cmd/github.handler.ts`：`shareBaseUrl = "https://dev.opencode.ai" | "https://opencode.ai"`，`/s/{shareId}` 分享链接 + `social-cards.sst.dev` 社交卡片图
- 作用：`gyc github` 工作流把会话/CI 结果分享为可读链接

### 自建方案
1. **分享 API**（Bun + Effect + SQLite）：
   - `POST /s` 创建分享（会话 JSON 快照 → 短 ID）
   - `GET /s/{id}` 返回渲染页（只读、无脚本注入风险）
   - 短 ID 使用 `nanoid`，支持过期与撤销
2. **渲染页**：静态生成式（HTML + 内置 JSON），不依赖前端框架，防 XSS
3. **社交卡片**：自建 `/og/{id}.png`（用 sharp 或 satori 生成），替代 `social-cards.sst.dev`
4. **客户端改造**：`shareBaseUrl` 改为环境变量 `GYCCODE_SHARE_URL`，默认自建服务

### 验收标准
- 分享 → 打开链接 → 渲染会话，全程无第三方域名
- 社交卡片图自建生成
- 未登录可读（只读公开链接），可撤销

## 三、额度体系（替代 opencode.ai/go）

### 现状依赖点
- `src/gyccode/session/retry.ts`：`GO_UPSELL_URL = "https://opencode.ai/go"` + `workspace/{id}/go`
- `src/tui/component/dialog-retry-action.tsx`：`GO_URL`
- 作用：opencode 免费模型 429 限流时的升级引导

### 自建方案
1. **配额服务**（并入账号服务或独立）：
   - 免费额度：按账号/设备记配额（请求数、Token 数），Redis/SQLite 计数
   - 限流策略：429 + Retry-After，复用现有 retry 逻辑
2. **升级入口**：自建定价页 `https://{domain}/upgrade`，替代 opencode.ai/go
3. **客户端改造**：`GO_UPSELL_URL` / `GO_URL` 改为环境变量 `GYCCODE_UPGRADE_URL`，默认自建页
4. **降级兜底**：未配置自建服务时，429 提示改为"额度用尽，请更换 provider 或稍后重试"（不跳第三方）

### 验收标准
- 429 提示不出现 opencode 域名
- 配额计数与限流生效
- 未配置时优雅降级（纯提示，无跳转）

## 遗留边界（如实披露）

- **默认值仍是第三方**：`console.opencode.ai`（账号）、`models.opencode.ai`（模型目录）在未配置环境变量时仍是默认值——功能可用性优先；配置 `GYCCODE_ACCOUNT_URL` / `GYCCODE_MODELS_URL` 即切自建
- **模型网关未自建**：gyccode 免费模型网关（真实 LLM 转发）依赖第三方，自建需 LLM 供应商中转（超出账号/分享/额度范围）
