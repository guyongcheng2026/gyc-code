## 三、归纳（可复用规律）

1. **Effect.withFiber 回调内同步 throw 会被转成不透明 `{}` Die**（真实错误丢失）。凡在 withFiber 回调里做可能抛异常的原生调用（sqlite prepare 等），必须放进 try 内并转成类型化错误，否则上层 catch 全部失效。
2. **Effect 4.0.0-beta.83 API**：无 `Effect.either`、无 `Cause.failures`（函数式）；用 `Effect.exit` + `Cause.squash(cause)` 检查错误实例。
3. **sqlite.bun/node layer 在孤立测试环境不可靠**：合法 SQL 也会因 `Context.get(fiber.context, Client.SafeIntegers)` 等上下文缺失产生 `{}` Die。测试私有 run() 用"镜像 run() 模式"的结构回归测试更务实。
4. **TUI 的 `.catch((err) => ({error: err}))` error-as-value 是正确模式**——关键在调用方是否判别 `result.error` 并处理，不可见 `.catch` 就报缺陷。
5. **空 catch 判定**：JSON 解析回退 / 可选清理 / best-effort 安装操作（chmod/unlink/symlink）属安全用法；只有吞掉影响可观测性或正确性的真实错误才算缺陷。
