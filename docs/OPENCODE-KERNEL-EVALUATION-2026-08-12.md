## 二、四大风险

### 1. 冻结风险（已缓解）
opencode 上游持续发布（当前 1.18.16）。**2026-08-12 已把内核从基线 v1.18.14 合并升级至 1.18.16**（11 个文件全部为 TUI 层：光标样式/消息排序/revert 修复/剪贴板/导出排序），core/schema/llm/codemode/server 零变更。未来上游发 1.18.17+ 时，按同样流程：`git diff 基线..新tag` 提取变更 → 手动移植（保留本地化）→ 构建+测试验证。

### 2. 升级成本
想升级内核 = 重新 diff 合并上游 → 与 gyc 的本地化改造（gyccode 品牌、依赖剥离、协议本地化）**必然冲突**，合并成本高于重写。上次依赖剥离就是 971 文件级别的大工程。

### 3. 供应链风险
121 个第三方 npm 包各自有上游生命周期：ai-sdk 频繁发版、effect 是 beta（0.4.0-beta.83）、tree-sitter 原生模块（Windows 兼容风险）。**任一包的安全漏洞或弃更都会传导到 gyc**，且无法随上游 opencode 一起升级。

### 4. 自研替代成本
完全重写 8.98 万行（含 TUI 渲染、LSP 客户端、provider 生态）≈ 数十人月，**负 ROI**（已两次否决）。

## 三、选项对比

| 选项 | 成本 | 收益 | 风险 | 结论 |
|------|------|------|------|------|
| **A. 维持冻结现状** | 零 | 无 | 安全漏洞永久暴露；新功能缺失 | ⚠️ 可行，但需配套监控 |
| **B. 定期合并上游** | 每次 971 文件级大工程 | 跟上游补丁/功能 | 与本地化冲突、合并引入回归 | ❌ 不推荐 |
| **C. 战略重写核心模块** | 每模块 1-2 周 | 关键路径可控 | 重写引入新 bug | ⭕ 按需触发（模块出问题才做） |
| **D. 完全重写** | 数十人月 | 彻底独立 | 极高，负 ROI | ❌ 已否决 |

## 四、建议（务实路径）

1. **建立上游安全监控**（零成本，立即做）：
   - 订阅 opencode GitHub Releases / Security Advisories
   - 关键 CVE 到达时，**手动打补丁到 vendored 对应文件**（外科手术式，单文件级）
2. **维持冻结 + 不合并上游**：gyc 已品牌化/依赖剥离，合并 ROI 为负
3. **战略重写按需触发**：仅当某模块（如 LSP、TUI 渲染）反复出 bug 或需新能力时，单模块重写
4. **依赖治理**：对 121 个依赖建立版本冻结清单 + 定期审计（bun audit）；重点关注 beta 版 effect 系与原生模块（tree-sitter/node-pty/photon）

## 五、结论

- **代码层已无可删**（品牌/依赖/URL 全清，法律与生态保留项除外）
- **内核已与上游 1.18.16 对齐**（2026-08-12 合并，基线 v1.18.14 → 1.18.16，11 文件 TUI 层补丁）
- **内核层的真实差距 = 未来上游版本的跟进**，低代价可闭环（单次合并约 11 文件）
- 治理成本估计：**每次上游 patch 约 1-2 小时**（diff 提取 + 手动移植 + 构建测试），远低于自研重写
- 综合口径：**代码独立 + 法律合规 + 依赖剥离 + 内核同步上游（1.18.16）+ 安全监控 = 完整闭环**
