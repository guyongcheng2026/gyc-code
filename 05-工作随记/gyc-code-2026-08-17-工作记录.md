## 四、NVIDIA promptCacheKey 根因与修复（本次核心坑）

### 现象
`gyc run -m nvidia/nvidia/nemotron-3-ultra-550b-a55b` 报 400：`Validation: Unsupported parameter(s): promptCacheKey`

### 根因
`C:\Users\谷勇成\gyc-cli\src\gyccode\provider\transform.ts` 第 1151-1163 行 `options()` 函数：

```ts
if (input.providerOptions?.setCacheKey !== false) {
  if (
    input.model.api.npm === "@ai-sdk/openai" ||
    input.model.api.npm === "@ai-sdk/azure" ||
    input.model.api.npm === "venice-ai-sdk-provider" ||
    input.model.api.npm === "@ai-sdk/openai-compatible" ||  // nvidia 走此分支
    input.providerOptions?.setCacheKey === true
  ) {
    result["promptCacheKey"] = input.sessionID
  }
}
```

nvidia catalog 的 npm 包为 `@ai-sdk/openai-compatible`，gyc 默认注入 `promptCacheKey = sessionID`，NVIDIA API 不支持该参数。

### 修复
`gyccode.json` nvidia provider 配置加：

```json
"nvidia": {
  "name": "NVIDIA",
  "env": ["NVIDIA_API_KEY"],
  "options": { "setCacheKey": false }
}
```

修复后实测成功。

### 经验教训
1. 新接 openai-compatible 类第三方 provider 若遇 400 "Unsupported parameter(s)"，先查 promptCacheKey
2. 换模型 EOL 会先报 410 Gone，需查 catalog 中在线模型
3. dist 过期构建会导致诡异崩溃（本次 `y.get(...).addError is not a function`），排查顺序：先 `bun run build` 再深挖
