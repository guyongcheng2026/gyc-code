## 四、乱码修复（TUI 底部不断刷新乱码）【commit `7022fb8`】

### 现象
- 运行 gyc 时，TUI 底部 spinner（Braille 盲文点阵字符）与中文状态文本不断闪烁乱码

### 根因
- opentui 渲染以 UTF-8 字节流写入 stdout（实测 Braille `⠋` = 字节 `E2 A0 8B`）
- conhost 默认代码页 936（GBK）把 UTF-8 字节按 GBK 解码 → 乱码；Windows Terminal 本身 UTF-8 无此问题

### 修复
- `src/tui/terminal-win32.ts` 新增 `win32EnableUtf8Console()`：kernel32 `SetConsoleOutputCP(65001)`
- `src/gyccode/index.ts` 进程入口启动时调用（幂等；仅 win32 + stdout TTY 生效）
- 退出不恢复代码页，避免同一控制台后续 bun/node/git 输出再次乱码

### 验证
- 构建通过；dist 产物确认含调用；TUI 冒烟 6 秒存活无报错
- 生效方式：重启 gyc（旧实例仍为旧代码）

## 五、LLM 选择不了 + 大计划执行一半退出【commit `2fd7f74`】

### 现象
- TUI `/models` 选不了 LLM；`gyc providers list` 直接崩溃
- 大计划执行到一半进程退出

### 根因
- commit `74d8da8` 适配 effect v4 时，把 `Schema.Literal("a","b","c")` 错改为多参数 `Schema.Union(Schema.Literal("a"), ...)`
- effect 4.0.0-beta.83 的 `Schema.Union` 只接受数组参数 → 模块顶层执行即抛 `members.map is not a function`，不再是被忽略的多余参数
- 受影响 4 个文件（hook/types.ts、permission/modes.ts、tool/brief.ts、tool/shell/security.ts）被 provider 列表与工具注册链加载 → 启动即崩

### 修复
- 4 个文件改用 `Schema.Literals([...])` 数组形式
- hook/types.ts 的 `Schema.Int.pipe(Schema.greaterThan(0))` → `Schema.check(Schema.isGreaterThan(0))`
- 重新 `bun run build`

### 验证
- 4 个模块 import 正常；`gyc providers list`、`gyc models` 输出完整模型列表
- `gyc run "say hi" --model deepseek/deepseek-chat` 完整会话：LLM 流式回复 + 16 个工具注册 + 正常退出
