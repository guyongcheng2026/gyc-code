## 一、故障现象

`gyc` 命令无法启动：

```
PS C:\Users\谷勇成> gyc
error: No such built-in module: node:sqlite
Bun v1.3.14 (Windows x64)
```

## 二、根因分析

1. **项目方向**：`build.mjs` 默认 `GYC_RUNTIME=node`，打包条件 `["node","browser"]` → `#sqlite` 解析到 `sqlite.node.ts` → dist 产物为 **Node 目标**（含 `import { DatabaseSync } from "node:sqlite"`，需 Node ≥ 22.5）。
2. **入口矛盾**：`bin/gyc` 在 Bun 环境（`typeof Bun !== "undefined"`）下优先 `import(dist/index.js)`，加载的却是 Node 目标产物；Bun 1.3.14 不支持 `node:sqlite` → 崩溃。
3. **触发面**：谷总本机 `gyc.exe` 安装在 `.bun/bin`（Bun 全局链接），必然走 Bun 分支。

## 三、修复方案（commit `84e2360`）

采用**构建运行时标记**方案（O(1) 判断、零误判，避免启动时全扫 285 个 chunk）：

1. `build.mjs`：构建完成后写入 `dist/RUNTIME` 标记（内容 `node` / `bun`）。
2. `bin/gyc`：
   - Bun 分支：标记为 `bun` → 进程内 `import`（冷启动最快）；否则（`node` 或无标记，默认 node）→ 交给 Node 子进程直跑 dist。
   - Node 分支：标记为 `bun` → spawn Bun 跑（防御性）；否则直接 `import` dist。
   - 新增 `findNode()` / `findBun()`，支持 `GYC_NODE` / `GYC_BUN` 环境变量覆盖。

最终产物恢复为 node 目标（项目默认方向），`dist/` 不入库（.gitignore）。
