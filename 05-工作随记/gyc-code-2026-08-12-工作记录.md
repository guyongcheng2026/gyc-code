## 一、现象

- TUI / Compose 会话运行 DeepSeek V4 Flash 时报错：
  `LLM stream connection idle timeout: no data received within 300000ms. The connection may have dropped.`
- 会话中断，gyc cli 无法继续正常运行

## 二、排查结论

- 根因 1：`llm-timeout.ts` 流空闲超时默认 300s（5 分钟），DeepSeek V4 Flash（opencode 免费通道 / 代理排队）首 token 延迟或连接 hang 可超过该窗口
- 根因 2：超时错误消息 `connection idle timeout / no data received` 不匹配 `retry.ts` 的 `RETRYABLE_MESSAGE_PATTERNS`，被判为不可重试 → 直接失败终止，而非自动重试恢复

## 三、修复（commit `da08605`）

1. `src/gyccode/session/retry.ts`：`RETRYABLE_MESSAGE_PATTERNS` 增加 `idle` 关键词与 `/\bidle timeout\b|no data received/i`，空闲超时错误进入自动重试（最多 5 次，指数退避 2s→30s）
2. `src/gyccode/session/llm-timeout.ts`：默认 `LLM_STREAM_IDLE_TIMEOUT_MS` 300s → 600s（10 分钟），适配 DeepSeek V4 慢首 token
3. `src/core/v1/config/config.ts`：schema 描述默认值同步 600000
4. 新增 `retry.test.ts`（idle timeout 可重试 / 普通错误不可重试）；更新 `llm-timeout.test.ts` 断言
5. 用户配置 `~/.config/gyccode/gyccode.json` 增加 `llm.stream_idle_timeout_ms: 600000`（立即生效，无需等发布）

## 六、全面稳定性排查（2026-08-12）

> 目标：发热 / 噪音 / 10 子代理并行 / 超时断 LLM / 24h 稳定运行

### 现象与证据

- 昨晚（08-11 23:14）日志：同一批 8 个并行子代理会话被 Abort，其中 1 个触发 `LLM stream connection idle timeout 300000ms`（旧版默认值），大量 summary 流报 `stream error`（provider=opencode，model=deepseek-v4-flash-free）
- 根因链：10 子代理并行 → 10+ 并发 LLM 流同时打到 opencode 免费通道 → 排队/限流 → 首 token 超时断流；同时并发叠加抬高 CPU 峰值（发热/噪音）
- 代码证据：`core/background-job.ts` 所有 job 无并发上限；task/swarm 无子代理数量上限（仅 depth 限制）；LLM 流无全局并发控制

### 修复（commit `4656ac6`）

1. `src/gyccode/session/llm.ts`：全局 `Semaphore` 并发闸，所有 LLM 流（主会话 + 子代理 + summary）最多 `max_concurrent_streams` 个并发，多余排队等待，不再并发轰炸 provider
2. `src/gyccode/session/llm-timeout.ts`：`LLM_MAX_CONCURRENT_STREAMS = 6` + `resolveMaxConcurrentStreams`
3. `src/core/v1/config/config.ts`：新增 `llm.max_concurrent_streams` 配置项（默认 6，可调）
4. 谷总 `gyccode.json` 已配置 `max_concurrent_streams: 6`

### 排查结论（无需改动）

- TUI 渲染循环：空闲时 live 计数归零自动暂停，无持续空转
- spinner：`animations_enabled` 默认关闭 → 静态符号，无动画开销；`BgPulse` 同样默认关闭
- 日志：已有 10MB 轮转（gyccode.log → .log.1）+ 串行写队列
- watcher：@parcel/watcher + ignore 模式，仅监听工作目录
- tokenizer WASM：仅 compaction/记忆提取时调用，非每 token 热点
- WebSocket（openai responses）有独立 idle timeout 保护；谷总走 SSE 非该路径
